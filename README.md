# Field App Orchestrator

現場の作業者が頭に付けたiPhoneを、Macから操作するためのシステムです。対象は、一人称視点の動画を集めるアプリのMinute DataとClaru AIです。

どちらのアプリも、録画は一定時間で区切られます。区切りのたびに完了後の画面を処理し、タスクを選び、録画を始め直す必要があります。そのままでは、作業者が手を止めてiPhoneを触ることになります。このシステムでは、この操作をMacが代わりに行います。撮影が始まってから人がするのは、休憩に入るときに止めて、戻ったときに再開することだけです。

## 動き方

Macは、iPhoneに今どの画面が出ているかを読み取り、目的の状態に近づくボタンを一つだけ押します。押した後は画面を読み直し、また次の一つを決めます。目的の状態は次の2つです。

- 撮影を続ける：録画中であること。録画が上限の長さで終わって完了画面が出たら、保存か破棄をして次の録画を始める
- 止める：録画していないこと。休憩のときに使う。止めた状態に着いた後は次の指示まで何も押さないので、休憩中に人がiPhoneを使っても邪魔をしない

どのボタンを押すかは、アプリごとの操作定義から計算します。操作定義には、アプリの画面の見分け方と、各画面で押せるボタンとその行き先を書きます。Macは、今の画面から目的の状態までの道順をこの地図から求め、その最初の一歩だけを押します。そのため、作業者が画面を触って別のタブやダイアログに移っても、次の一歩はその画面から決まります。

時間は数えません。録画の終わりは、録画中の画面が変わったこと（Minuteでは上限に達したお知らせが出たこと）で知ります。Minuteで撮影を続けている間は、次の一周を繰り返します。

```text
録画中 → 上限の長さで終了 → 上限に達したお知らせ（OK） → 完了画面 → 保存または破棄 → 確認 → 録画待機 → 録画 → カウントダウン → 録画中
```

保存するか破棄するかは、操作定義で選びます。止めたときは、カメラを切ったタスクの説明カードで待ちます。

Macへの指示は、すぐにタップへ変えるのではなく、撮影を続けるか止めるかという目標として記録します。iPhoneには操作を一つずつ送り、次に何をするかは、そのたびに最新の目標と画面から決めます。そのため、いつ指示を変えても、二つの操作が同時に送られることはありません。Macのプログラムを起動した直後は、最初の指示が来るまで画面を読むだけで何も押さないので、録画中に起動し直しても録画はそのまま続きます。撮影を続ける指示の間にMacのプログラムが落ちたときだけは、起動し直した後にその指示を引き継いで、続きから進めます。

複数のiPhoneを使うときは、1台ごとにMac上でプログラムを1つ起動します。そのiPhoneを操作するのはそのプログラムだけで、1台が止まっても他のiPhoneは動き続けます。

MacとiPhoneのやり取りは、画面の部品の名前を問い合わせる小さな文字のやり取りだけで、画像は送りません。録画中や止めた状態のように落ち着いている間は10秒に1回だけ画面を見るので、1分あたりの問い合わせは7回ほどです。指示が届いたときは、待たずにすぐ動きます。

## 装着者が止める・再開する

装着者は、iPhoneの背面を3回たたくと撮影を始め、2回たたくと止めます。どちらもiOSの背面タップで動くショートカットで、まずiPhoneの中で「撮影の準備をしています。お待ちください。」または「撮影を終了しています。お待ちください。」と読み上げ、それからMacに指示を送って、返ってきた文を読み上げます。Macは、指示のあとに画面を読み、録画が始まった、止まった、人の確認が要る、といった結果が出てから返します（最長30秒）。

画面が見えなくても、聞こえた声でわかります。最初の文が聞こえなければ背面タップが認識されておらず、その後の文が聞こえなければ指示はMacに届いていません。

設定の手順と返す文は[iPhoneとMacの準備と運転](docs/operations/device-setup.md#背面タップで止める再開する)にあります。

## 自動で立て直すこと

- Macとの接続が切れたとき（Wi-Fiの切断、WebDriverAgentの終了、音量ボタンの同時押し）は、10秒おきにつなぎ直し、つながったら画面を読んで続きから進めます。Minuteは接続と関係なく録画を続けます。iPhone上のWebDriverAgent（Macからの操作を受けるアプリ）が止まっていれば、Macが起動し直します。iPhoneがWi-Fiの外にいる間は、起動し直さずに戻るのを待ちます。
- Macのプログラムが落ちたときは、サービスとして登録していれば自動で起動し直され、撮影を続ける指示を引き継いで続きから進めます。
- ボタンを押した直後に返事が途絶えたときも、同じボタンを押し直さず、つながった後の画面を読んで次を決めます。
- 押したのに画面が変わらなかったときは、アプリが取りこぼしたとみなし、画面を読み直してから押し直します。押そうとしたボタンが押す前や押す瞬間に消えていたときも、画面を読み直して次を決めます。
- Minuteが前面にないときは前面に戻し、終了されていれば起動します。ほかのアプリやホーム画面のほか、コントロールセンター、通知センター、アプリの切り替え画面が開いているときも同じです。iPhoneがロックされていれば、解除してから戻します。
- 操作定義にない画面にいるとき、または押すボタンが操作定義にないシートやダイアログに覆われているときは、そのボタンを押さずに、アプリを起動し直して知っている画面から進めます。ただし、起動し直すと撮ったものが失われる画面では起動し直しません。どの画面がそれに当たるかは操作定義に書き、Minuteでは録画の画面です。
- 操作定義に書いたiOSの警告（電池残量の警告など）は、書いたボタン（「閉じる」）で閉じて続けます。それ以外の警告では人を待ちます。
- 電池が残り10%（`FAO_BATTERY_STOP_PERCENT`で1〜50に変えられる）になり、充電していないときは、止める指示を出してMacに通知します。

## 迷ったときは押さずに止まる

次のときは、ボタンを押さずにそのiPhoneの操作を止め、人の確認を待ちます。

- 操作定義にない画面にいて、そこが起動し直さない画面である、または起動し直しても知っている画面に戻らない
- 押すボタンが見つからない、または同じ目印のボタンが複数ある
- 操作定義に書いていないiOSの警告（権限の確認など）が出ている
- iPhoneがロックされていて解除できない（パスコードが設定されている）
- 何度か押しても、目的の状態にならない

人が画面を確かめて、`retry`を入力するか、新しく指示を出す（背面タップを含む）と、画面を読み直して再開します。

## アプリごとの違い

画面の見分け方、押すボタン、その行き先はアプリごとに違い、どれも操作定義というJSONファイルに書きます。画面やボタンは、アプリが画面の部品に付けているアクセシビリティの名前を目印にして見分けます。

Macのプログラムは一つで、iPhoneごとにMinute用かClaru用の操作定義を読み込んで動きます。対応するアプリを増やすときは、プログラムには手を入れず、`apps/<アプリ名>/`に操作定義を追加します。

書き方は[操作定義の形式](docs/app-operation-format.md)にあります。

## リポジトリ構成

```text
apps/
  minute-app/          Minute Dataの操作定義と設定手順
  claru-app/           Claru AIの操作定義のひな形と設定手順
mac/
  controller-core/     Mac側のプログラム field-app とテスト
docs/                  設計と運用の資料
tools/                 WebDriverAgentの組み立て、サービスの登録、公開前の検査
```

## 使い方

iPhone 1台ごとに`field-app`を起動します。確かめるときはターミナルから起動し、現場ではサービスとして登録します。複数台をまとめて操作するMacアプリは、実機での確認が済んでから作ります。

### 1. MacとiPhoneを準備する

Xcodeを入れたMacに、iPhoneを一度USBでつないで信頼し、デベロッパモードをオンにします。それからは、MacとiPhoneを同じWi-Fiにつなげば、ケーブルなしで操作できます。パスコードはオフ、自動ロックは「なし」にします。対象アプリへのログインと、必要な権限の許可も済ませておきます。詳しくは[iPhoneとMacの準備と運転](docs/operations/device-setup.md)に、工場出荷状態のiPhoneから順に進める手順は[iPhoneの初期設定](docs/operations/iphone-setup.md)にあります。

iPhoneで動かすWebDriverAgentを、一度だけ組み立てます。

```sh
FAO_DEVELOPMENT_TEAM=<Team ID> tools/setup_wda.sh <iPhoneのUDID>
```

### 2. 操作定義を用意する

Minuteの操作定義の例をコピーし、撮るタスクの名前を入れます。次の例ではFood Prepにしています。

```sh
mkdir -p config/local
sed 's/REPLACE_WITH_TASK_TITLE/Food Prep/g' apps/minute-app/definition.example.json > config/local/minute.json
swift run --package-path mac/controller-core field-app \
  --validate-definition config/local/minute.json
```

検証では、値の入れ忘れがないことと、どの画面からも2つの目的の状態にたどり着けることを確かめます。

### 3. 起動して指示する

端末ごとの起動コマンドは、[Minute Data](apps/minute-app/README.md)と[Claru AI](apps/claru-app/README.md)の設定手順にあります。背面タップを使うときは、起動するときに`FAO_CONTROL_PORT`と`FAO_CONTROL_TOKEN`も与えます。

ターミナルからは、次の言葉を入力して指示します。

| 入力 | 動作 |
| --- | --- |
| `start` | 撮影を続ける |
| `pause` | 止める |
| `status` | 今の指示、画面、止まっているかどうかを表示する |
| `retry` | 止まった後、人が画面を確かめてから再開する |
| `quit` | 止めた状態にしてから終了する |

Ctrl-Cを押したときやターミナルを閉じたときも、`quit`と同じく止めた状態にしてから終了します。人の確認を待っている間やiPhoneにつながっていない間に終了すると、止めた状態を確かめられなかったことを表示します。

動いている間は、読み取った画面、進めた一歩（押したボタン、警告を閉じる、アプリを前面に戻すなど）、状態の変化を時刻つきで表示します。

現場では、`field-app`をサービスとして登録します。Macにログインすると起動し、落ちたときは起動し直され、表示はログファイルに出ます。背面タップのショートカットに書くMacの名前は、Macの個体の名前ではなく、現場のMacに付ける役割の名前にします。どちらも[iPhoneとMacの準備と運転](docs/operations/device-setup.md#サービスとして動かす)にあります。

```sh
tools/service.sh install config/local/minute-01.env config/local/minute.json
```

### 開発

```sh
swift test --package-path mac/controller-core
swift build -c release --package-path mac/controller-core
```

## 現在地

- Minute 1.29.0の実機（iPhone 12 mini、iOS 26.4.1）で、次を確かめました。試運転のため、録画はすべて破棄しています。
  - USBケーブルを抜き、Wi-FiだけでMacとつないだ状態で、止めた後に人が残しうる次の状態から録画を始めて止める。ほかのアプリ、ホーム画面、コントロールセンター、通知センター、アプリの切り替え画面、検索、画面のロック、Minuteの終了、電池残量の警告と同じ文と同じボタンの警告（Safariで出したもの）、操作定義にないMinuteの画面（設定の中の画面）、タブを覆うシート（設定の言語の選択）、下までスクロールしたタスク一覧
  - Wi-Fiだけでつないだ状態で、WebDriverAgentを終了されても、Macが起動し直して約14秒で操作に戻る。録画は途切れない
  - Wi-Fiだけでつないだ状態で、録画中にMacのプログラムを起動し直しても、録画を止めない
  - タスク一覧、別のタブ、タスクの説明カードのどこからでも、撮るタスクを探して録画を始める
  - 上限の30分で録画が終わると、上限に達したお知らせを閉じて録画を破棄し、約20秒で次の録画を始める（USBでつないだ状態で確認）
  - 録画中に止めると、録画を止めて破棄し、カメラを切った説明カードで待つ。1分未満で止めたときのダイアログにも対応する
  - 1つの背面タップで開始と停止を切り替えていた形で、ショートカットからの指示が届き、開始と停止が切り替わる
  - Macから`/start`と`/pause`の要求を送ると、画面で結果を確かめてから返事をする。説明カードからの開始は17〜20秒で「撮影を開始しました。」を、録画中からの終了は約10秒で「撮影を終了しました。」を返す。操作定義にない警告が出ているときは、1回目に表示を閉じるよう求め、2回目に担当者への連絡を求め、警告を閉じた後の指示で録画を始める。WebDriverAgentが止まっているときは、つながっていないことをすぐに返し、起動し直して約30秒後に録画を始める
  - 録画中に画面がロックされると、Minuteは録画をそこで止めて完了画面に移る。Macは解除して完了後の操作をし、約20秒で次の録画に戻る
  - 録画中にMinuteを終了されると、撮りかけは失われる。MacはMinuteを起動し直し、タスクを探して約80秒で録画に戻る
  - 落ち着いている間の問い合わせは1分に7回で、以前の78回から減った
  - `quit`とCtrl-Cで、止めた状態にしてから終了する
  - サービスとして登録した`field-app`が、WebDriverAgentを起動し、Macからの`/start`と`/pause`で録画を始めて止める。動いている間、Macのスリープを自分で防ぐ
  - 撮影を続ける指示を受けた直後に`field-app`を強制終了すると、1秒で起動し直され、指示を引き継いで録画まで進む。WebDriverAgentは動いたままで、そのまま使う
  - サービスを止めると、録画を止めて破棄し、説明カードまで進めてから終わる。その後に起動したときは、最初の指示まで何も押さない
  - launchdから起動したプログラムの受け口に、iPhoneがMacのローカルホスト名で届く（iPhoneのSafariから、試験用の受け口で確認）
- 保存の流れ（保存、確認、同じタスクで続ける）は実機で一度確かめましたが、保存しながら続けて運転するのはまだです。
- 電池の見張りはテストだけで確かめています。
- 開始と終了の背面タップのショートカットからは、まだ確かめていません。上の`/start`と`/pause`の確認は、Macから同じ要求を送ったものです。
- Claru AIの画面はまだ調べていません。
- 次に確かめるのは、開始と終了の背面タップ、Macを再起動してログインした後のサービスの起動、Wi-Fiが途切れて戻ったときの立て直し、Wi-Fiだけでつないだ8時間の連続運転、2台同時の運転です。
