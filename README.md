# Field App Orchestrator

現場の作業者が頭に付けたiPhoneを、Macから操作するためのシステムです。対象は、一人称視点の動画を集めるアプリのMinute DataとClaru AIです。

どちらのアプリも、録画は一定時間で区切られます。区切りのたびに完了後の画面を処理し、タスクを選び、録画を始め直す必要があります。そのままでは、作業者が手を止めてiPhoneを触ることになります。このシステムでは、この操作をMacが代わりに行います。撮影が始まってから人がするのは、休憩に入るときと戻ったときに、Macで一時停止と開始を指示することだけです。

## 動き方

Macは、iPhoneに今どの画面が出ているかを読み取り、その画面で押すボタンを決めて押します。押した後はもう一度画面を読み取り、次の操作を決めます。

画面は、ホーム、録画の開始前、録画中、録画の完了後の4つに分けて扱います。どの画面で何を押すかは、Macで開始と一時停止のどちらを指示しているかによって変わります。この組み合わせは、アプリごとに用意する操作定義というJSONファイルに書きます。たとえば次のように書くと、開始している間は録画が区切られるたびに次の録画を始め、一時停止するとホームで待ちます。

| 画面 | 開始を指示しているとき | 一時停止を指示しているとき |
| --- | --- | --- |
| ホーム | 決めておいたタスクを開く | 何もしない |
| 録画の開始前 | 録画を始める | ホームへ戻る |
| 録画中 | 何もしない | 録画を止める |
| 録画の完了後 | 完了後の操作をする | 完了後の操作をする |

完了後に押すボタンも操作定義で決めるので、提出する、破棄する、人の確認を待つ、のどれにもできます。

Macからの指示は、すぐにタップへ変えるのではなく、録画を続けるか止めて待つかという目標として記録します。iPhoneには操作を一つずつ送り、次に何をするかは、そのたびに最新の目標と画面から決めます。そのため、いつ指示を変えても、二つの操作が同時に送られることはありません。

複数のiPhoneを使うときは、1台ごとにMac上でプログラムを1つ起動します。そのiPhoneを操作するのはそのプログラムだけで、1台が止まっても他のiPhoneは動き続けます。

## アプリごとの違い

画面の見分け方、押すボタン、どの画面で何を押すかは、アプリごとに違い、どれも操作定義に書きます。画面やボタンは、アプリが画面の部品に付けているアクセシビリティ識別子を目印にして見分けます。

Macのプログラムは一つで、iPhoneごとにMinute用かClaru用の操作定義を読み込んで動きます。対応するアプリを増やすときは、プログラムには手を入れず、`apps/<アプリ名>/`に操作定義を追加します。今の形式は4つの画面とボタンを押す操作だけを扱います。これで表せない手順のアプリが出てきたら、そのときに形式を広げます。

書き方は[操作定義の形式](docs/app-operation-format.md)にあります。

## 迷ったときは押さずに止まる

次のときは、ボタンを押さずにそのiPhoneの操作を止め、人の確認を待ちます。

- 今の画面が4つのどれにも当てはまらない、または複数に当てはまる
- 押すボタンが見つからない、または同じ目印のボタンが複数ある
- 操作定義に登録したログイン、権限の確認、警告の画面が出ている
- ボタンを押した後、押せたかどうかの返事が通信の途中で失われた
- 決められた回数だけ操作しても、指示した状態にならない

人が画面を確かめて`retry`を入力すると、画面を読み取り直して再開します。

## リポジトリ構成

```text
apps/
  minute-app/          Minute Dataの操作定義の例と設定手順
  claru-app/           Claru AIの操作定義の例と設定手順
mac/
  controller-core/     Mac側のプログラム field-app とテスト
docs/                  設計と運用の資料
tools/                 Appiumのセットアップと公開前の検査
```

## 使い方

今は、iPhone 1台ごとにターミナルで`field-app`を起動し、キーボードから指示します。複数台をまとめて操作するMacアプリは、実機での確認が済んでから作ります。

### 1. MacとiPhoneを準備する

iPhoneをMacにつなぎ、Macを信頼し、デベロッパモードをオンにします。対象アプリへのログインと、必要な権限の許可も済ませておきます。詳しくは[Appium実機開発](docs/operations/appium-development.md)にあります。

```sh
npm run setup:appium
npm run doctor:appium
npm run appium
```

`npm run appium`で起動するAppiumサーバーは一つだけで、複数のiPhoneで共有します。

### 2. 操作定義を用意する

操作定義の例を`config/local/`へコピーします。

```sh
mkdir -p config/local
cp apps/minute-app/course.example.json config/local/minute.json
```

`REPLACE_WITH_`で始まる値を、インストールされているアプリの版で調べたアクセシビリティ識別子に置き換え、検証します。置き換えていない値が残っていると、検証で弾かれます。

```sh
swift run --package-path mac/controller-core field-app \
  --validate-course config/local/minute.json
```

### 3. 起動して指示する

端末ごとの起動コマンドは、[Minute Data](apps/minute-app/README.md)と[Claru AI](apps/claru-app/README.md)の設定手順にあります。起動した直後は一時停止の状態です。次の言葉を入力して指示します。

| 入力 | 動作 |
| --- | --- |
| `start` | 開始する |
| `pause` | 一時停止する |
| `status` | 今の指示、画面、止まっているかどうかを表示する |
| `retry` | 止まった後、人が画面を確かめてから再開する |
| `quit` | 一時停止の状態にしてから終了する |

人の確認を待っている間に`quit`すると、ボタンを押さずに終了し、一時停止を確かめられなかったことを表示します。

### 開発

```sh
swift test --package-path mac/controller-core
swift build -c release --package-path mac/controller-core
```

## 現在地

- USBでつないだiPhoneで、AppiumからWebDriverAgentを起動し、使い回せることを確かめました。
- Minute用とClaru用の操作定義を、同じプログラムが読み込んで動かせます。
- 操作定義どおりに開始と一時停止を進めること、終了の前に一時停止まで進めること、4つのどれにも当てはまらない画面や同じ目印のボタンが複数ある場合に止まることは、テストで確かめています。実機ではまだ確かめていません。
- 本物のMinuteとClaruでは、まだ動かしていません。各アプリの今の版で目印を調べ、操作定義に入れてから試します。
- 次に確かめるのは、Wi-Fiでの接続、2台同時の運転、接続が切れたときの復旧、8時間の連続運転です。
