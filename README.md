# Field App Orchestrator

現場の作業者が頭に付けたiPhoneを、Macから操作するためのシステムです。対象は、一人称視点の動画を集めるアプリのMinute DataとClaru AIです。

どちらのアプリも、録画は一定時間で区切られます。区切りのたびに完了後の画面を処理し、タスクを選び、録画を始め直す必要があります。そのままでは、作業者が手を止めてiPhoneを触ることになります。このシステムでは、この操作をMacが代わりに行います。撮影が始まってから人がするのは、休憩に入るときにMacで止めて、戻ったときに開始することだけです。

## 動き方

Macは、iPhoneに今どの画面が出ているかを読み取り、目的の状態に近づくボタンを一つだけ押します。押した後は画面を読み直し、また次の一つを決めます。目的の状態は次の2つです。

- 撮影を続ける：録画中であること。録画が上限の長さで終わって完了画面が出たら、保存か破棄をして次の録画を始める
- 止める：録画していないこと。休憩のときに使う

どのボタンを押すかは、アプリごとの操作定義から計算します。操作定義には、アプリの画面の見分け方と、各画面で押せるボタンとその行き先を書きます。Macは、今の画面から目的の状態までの道順をこの地図から求め、その最初の一歩だけを押します。そのため、作業者が画面を触って別のタブやダイアログに移っても、次の一歩はその画面から決まります。

時間は数えません。録画の終わりは、録画中の画面が完了画面に変わったことで知ります。Minuteで撮影を続けている間は、次の一周を繰り返します。

```text
録画中 → 上限の長さで終了 → 完了画面 → 保存または破棄 → 確認 → 録画待機 → 録画 → カウントダウン → 録画中
```

保存するか破棄するかは、操作定義で選びます。

Macからの指示は、すぐにタップへ変えるのではなく、撮影を続けるか止めるかという目標として記録します。iPhoneには操作を一つずつ送り、次に何をするかは、そのたびに最新の目標と画面から決めます。そのため、いつ指示を変えても、二つの操作が同時に送られることはありません。

複数のiPhoneを使うときは、1台ごとにMac上でプログラムを1つ起動します。そのiPhoneを操作するのはそのプログラムだけで、1台が止まっても他のiPhoneは動き続けます。

## アプリごとの違い

画面の見分け方、押すボタン、その行き先はアプリごとに違い、どれも操作定義というJSONファイルに書きます。画面やボタンは、アプリが画面の部品に付けているアクセシビリティの名前を目印にして見分けます。

Macのプログラムは一つで、iPhoneごとにMinute用かClaru用の操作定義を読み込んで動きます。対応するアプリを増やすときは、プログラムには手を入れず、`apps/<アプリ名>/`に操作定義を追加します。

書き方は[操作定義の形式](docs/app-operation-format.md)にあります。

## 迷ったときは押さずに止まる

次のときは、ボタンを押さずにそのiPhoneの操作を止め、人の確認を待ちます。

- 今の画面が操作定義のどの画面にも当てはまらない、または複数に当てはまる
- 押すボタンが見つからない、同じ目印のボタンが複数ある、または何かに覆われて押せない
- iOSのダイアログ（権限の確認など）が出ている
- ボタンを押した後、押せたかどうかの返事が通信の途中で失われた
- 何度か押しても、目的の状態にならない

人が画面を確かめて`retry`を入力すると、画面を読み直して再開します。押したのに画面が変わらなかったときは、アプリが取りこぼしたとみなし、画面を読み直してから押し直します。

## リポジトリ構成

```text
apps/
  minute-app/          Minute Dataの操作定義と設定手順
  claru-app/           Claru AIの操作定義のひな形と設定手順
mac/
  controller-core/     Mac側のプログラム field-app とテスト
docs/                  設計と運用の資料
tools/                 Appiumのセットアップと公開前の検査
```

## 使い方

今は、iPhone 1台ごとにターミナルで`field-app`を起動し、キーボードから指示します。複数台をまとめて操作するMacアプリは、実機での確認が済んでから作ります。

### 1. MacとiPhoneを準備する

iPhoneをMacにつなぎ、Macを信頼し、デベロッパモードをオンにします。対象アプリへのログインと、必要な権限の許可も済ませておきます。詳しくは[Appium実機開発](docs/operations/appium-development.md)にあります。

```sh
npm run setup:appium
npm run doctor:appium
npm run appium
```

`npm run appium`で起動するAppiumサーバーは一つだけで、複数のiPhoneで共有します。

### 2. 操作定義を用意する

Minuteの操作定義の例をコピーし、撮るタスクの名前を入れます。次の例ではFood Prepにしています。

```sh
mkdir -p config/local
sed 's/REPLACE_WITH_TASK_TITLE/Food Prep/g' apps/minute-app/definition.example.json > config/local/minute.json
swift run --package-path mac/controller-core field-app \
  --validate-definition config/local/minute.json
```

検証では、値の入れ忘れがないことと、どの画面からも2つの目的の状態にたどり着けることを確かめます。

### 3. 起動して指示する

端末ごとの起動コマンドは、[Minute Data](apps/minute-app/README.md)と[Claru AI](apps/claru-app/README.md)の設定手順にあります。起動した直後は止めた状態です。次の言葉を入力して指示します。

| 入力 | 動作 |
| --- | --- |
| `start` | 撮影を続ける |
| `pause` | 止める |
| `status` | 今の指示、画面、止まっているかどうかを表示する |
| `retry` | 止まった後、人が画面を確かめてから再開する |
| `quit` | 止めた状態にしてから終了する |

Ctrl-Cを押したときやターミナルを閉じたときも、`quit`と同じく止めた状態にしてから終了します。人の確認を待っている間に終了すると、ボタンを押さずに終了し、止めた状態を確かめられなかったことを表示します。

動いている間は、読み取った画面、押したボタン、状態の変化を時刻つきで表示します。

### 開発

```sh
swift test --package-path mac/controller-core
swift build -c release --package-path mac/controller-core
```

## 現在地

- Minute 1.29.0の実機で、次を確かめました。試運転のため、録画はすべて破棄しています。
  - タスク一覧、別のタブ、タスクの説明カードのどこからでも、撮るタスクを探して録画を始める
  - 録画中に止めると、録画を止めて破棄し、カメラを切った説明カードで待つ。1分未満で止めたときのダイアログにも対応する
  - 再び開始すると録画に戻る
  - `quit`とCtrl-Cで、止めた状態にしてから終了する
- 保存の流れ（保存、確認、同じタスクで続ける）は実機で一度確かめましたが、保存しながら続けて運転するのはまだです。
- Claru AIの画面はまだ調べていません。
- 次に確かめるのは、上限の長さ（Minuteは30分）での区切りをまたぐ運転、Wi-Fiでの接続、2台同時の運転、接続が切れたときの復旧、8時間の連続運転です。
