# 0006: 前面のアプリは画面の中央で見分け、知らない画面からはアプリを起動し直して戻る

## 状況

装着者は休憩中にiPhoneを使い、戻ると背面タップで再開します。そのとき、iPhoneがどの画面にあっても録画に戻れる必要があります。

人が残しうる状態を実機で作って確かめたところ、次の場面で止まっていました。

- コントロールセンター、通知センター、アプリの切り替え画面が開いている。Appiumのセッションに対象アプリを指定していたため、WebDriverAgentはこれらの下にある対象アプリを前面のアプリとして読んでいた。通知センターと切り替え画面では、部品が押せないと返って人を待った。コントロールセンターでは部品が押せると返り、タップがコントロールセンターに当たった
- 設定の中の画面のように、操作定義にない画面にいる
- 設定の言語の選択のように、アプリの中のシートがタブを覆っている。下のタブの状態には当てはまるが、押す部品が覆われている

## 決定

セッションには対象アプリを指定せず、画面の中央にあるアプリを前面のアプリとして読みます。システムの画面が開いていれば対象アプリは前面にないと判断し、アプリを前面に戻す操作で閉じます。

どの状態にも当てはまらない画面と、押す部品が覆われている画面を、どちらも知らない画面として扱います。知らない画面のボタンは押しません。操作定義の`recovery`が許すときは、アプリを起動し直して、知っている画面から道順を決め直します。起動し直すと撮ったものが失われる画面は`recovery.relaunchUnless`に目印を書き、そこでは人を待ちます。起動し直すのは1回の判断の流れで一度だけです。

タブが見えている画面ではタスクのタブを押して戻る、という状態を操作定義に足す方法もありました。しかし、アプリの中の画面を一つずつ定義に足すことになり、シートが開いたままの画面ではタブを押せません。起動し直せば、どの画面からでも同じ方法で戻れます。

## 結果

- ほかのアプリ、ホーム画面、ロック、システムの画面、アプリの中の知らない画面やシートのどこからでも、録画に戻れる
- 起動し直すとタスク一覧から始まり、タスクを探し直すので、Minuteでは録画に戻るまで約1分かかる
- 起動し直すと、アプリの中で開いていた画面や入力の途中だった内容は失われる
- 録画の画面で知らない画面になったときは、これまでどおり人を待つ
- 0004の結果にある「地図にない画面、何かに覆われた部品では押さずに止まる」は、起動し直しを許さない定義と、起動し直さない画面にだけ当てはまる
