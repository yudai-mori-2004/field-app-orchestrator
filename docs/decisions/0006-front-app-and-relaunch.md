# 0006: 前面のアプリは画面中央で判定し、未定義の画面からはアプリの再起動で復帰する

## 状況

装着者は休憩中にiPhoneを使用し、戻ると背面タップで撮影を再開します。その際、iPhoneがどの画面にあっても録画に復帰できる必要があります。

人が操作した後に残りうる状態を実機で再現して確認したところ、次の場面で停止していました。

- コントロールセンター、通知センター、Appスイッチャーが開いている。Appiumのセッションで対象アプリを指定していたため、WebDriverAgentはこれらの背後にある対象アプリを前面のアプリとして読み取っていた。通知センターとAppスイッチャーでは、UI要素がタップ不可と返されて要対応状態になった。コントロールセンターでは、UI要素がタップ可能と返され、タップがコントロールセンターに当たった
- 設定内の画面など、操作定義にない画面にいる
- 言語設定のシートなど、アプリ内のシートがタブを覆っている。背後のタブの状態には該当するが、タップ対象のUI要素が覆われている

## 決定

セッションでは対象アプリを指定せず、画面中央にあるアプリを前面のアプリとして読み取ります。システムの画面が開いている場合は、対象アプリが前面にないと判定し、アプリを前面に戻す操作で閉じます。

どの状態にも該当しない画面と、タップ対象のUI要素が覆われている画面を、いずれも未定義の画面として扱います。未定義の画面では、ボタンをタップしません。操作定義の`recovery`で許可されている場合は、アプリを再起動し、定義済みの画面から経路を再計算します。再起動すると録画データが失われる画面は、`recovery.relaunchUnless`に識別要素を記述し、その画面では要対応状態になります。再起動は1回の制御ループにつき1回までです。

タブが表示されている画面ではタスクのタブをタップして戻る、という状態を操作定義に追加する方法もありました。しかし、アプリ内の画面を1つずつ定義に追加することになり、シートが開いたままの画面ではタブをタップできません。再起動すれば、どの画面からでも同じ方法で復帰できます。

## 結果

- 他のアプリ、ホーム画面、ロック画面、システムの画面、アプリ内の未定義の画面やシートのいずれからでも、録画に復帰できる
- 再起動するとタスク一覧から開始してタスクを再検索するため、Minuteでは録画への復帰に約1分かかる
- 再起動すると、アプリ内で開いていた画面や入力途中の内容は失われる
- 録画画面で未定義の画面になった場合は、従来どおり要対応状態になる
- 0004の結果にある「未定義の画面、何かに覆われたUI要素、iOSのダイアログでは、タップせずに停止する」は、再起動を許可しない定義と、再起動しない画面にのみ当てはまる
