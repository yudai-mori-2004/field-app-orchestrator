# 0008: 開始と終了を別の背面タップにし、結果を確かめてから返事をする

## 状況

[0005](0005-back-tap-trigger.md)では、トリプルタップ1つで撮影を続けると止めるを切り替え、指示を受けた直後に「撮影を始めます。」「撮影を止めます。」と返していました。

- 切り替えでは、たたいたときの結果がMacの今の目標で決まります。録画中に`field-app`を起動し直した後は目標がないので、止めるつもりでたたくと開始になります。返事が聞き取れずにもう一度たたくと、元に戻ります。
- 返事は、画面で結果を確かめる前に作っていました。人の確認を待っているときも、そのタップで待ちが解けた後に文を作るので、確認が要ることは読み上げられませんでした。読み直しても進めなかったことも、装着者には伝わりませんでした。

## 決定

- 開始をトリプルタップ（`POST /start`）、終了をダブルタップ（`POST /pause`）に分けます。切り替えの受け口（`/toggle`）はなくします。たたきやすいダブルタップを終了にするので、誤って止まることはありますが、読み上げで本人が気づけます。
- ショートカットは、まずiPhoneの中で「開始」「終了」と読み上げてから、Macに指示を送ります。
- `field-app`は、その指示のあとに画面を読んだ結果が出てから返事をします。結果は、目標に着いた、人の確認が要る、つながっていない、のどれかです。30秒で出なければ、途中であることを返します。Minuteの実機では、タスクの説明カードから録画が始まるまで、カウントダウンを含めて約20秒かかるので、ふつうの開始の結果が返る長さにしています。
- 人の確認が要るときは、画面に出ている表示を閉じてから、もう一度同じようにたたくことを求めます。それでも目標に着かずに人の確認が要れば、担当者への連絡を求めます。

## 結果

- 最初の声でタップが認識されたことが、次の文でMacに届いたことと結果がわかります。
- 返事は、結果が出るまで遅れます。Minuteの実機では、説明カードからの開始で約20秒、録画中からの終了で約10秒でした。最長で30秒です。
- Minuteを起動し直してタスクを探すときのように時間がかかる開始には「準備をしています」と返すので、その後に止まっても装着者には伝わりません。
- 返事の文はどちらの背面タップで送られたかを知らないので、「同じようにたたく」と書きます。
