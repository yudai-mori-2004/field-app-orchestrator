# 0008: 開始と終了を別の背面タップに分け、結果を確認してから応答する

応答の扱いは、[0011](0011-reply-when-the-mac-takes-the-command.md)で変更しました。

## 状況

[0005](0005-back-tap-trigger.md)では、トリプルタップ1つで撮影継続と停止を切り替え、指示の受信直後に「撮影を始めます。」「撮影を止めます。」と応答していました。

- 切り替え方式では、タップしたときの結果がMacの現在の目標状態で決まります。録画中に`field-app`を再起動した後は目標状態がないため、停止するつもりでタップすると開始になります。応答が聞き取れずに再度タップすると、元に戻ります。
- 応答は、画面で結果を確認する前に生成していました。要対応状態のときも、そのタップで要対応状態が解除された後に応答文を生成するため、確認が必要なことは読み上げられませんでした。読み取り直しても処理を進められなかったことも、装着者には伝わりませんでした。

## 決定

- 開始をトリプルタップ（`POST /start`）、終了をダブルタップ（`POST /pause`）に分けます。切り替えのエンドポイント（`/toggle`）は廃止します。タップしやすいダブルタップを終了に割り当てるため、誤って停止することはありますが、読み上げで本人が気付けます。
- ショートカットは、まずiPhone上で「撮影の準備をしています。お待ちください。」または「撮影を終了しています。お待ちください。」と読み上げてから、Macに指示を送信します。
- `field-app`は、その指示の後に画面を読み取った結果が出てから応答します。結果は、目標状態に到達した、要対応状態になった、接続できない、のいずれかです。30秒以内に結果が出なければ、時間がかかっていることを伝え、少ししてから再度タップするよう求めます。Minuteの実機では、タスクカードから録画開始まで、カウントダウンを含めて約20秒かかるため、通常の開始の結果が返る長さにしています。
- 要対応状態の場合は、画面に表示されている内容を閉じてから、再度同じようにタップするよう求めます。それでも目標状態に到達せずに要対応状態になった場合は、担当者への連絡を求めます。

## 結果

- 最初の音声でタップが認識されたこと、次の応答文でMacに届いたことと結果がわかります。
- 応答は、結果が出るまで遅れます。Minuteの実機では、タスクカードからの開始で約20秒、録画中からの終了で約10秒でした。最長で30秒です。
- Minuteを再起動してタスクを検索する場合など、時間がかかる開始では、少ししてから再度タップするよう求めます。再度タップすると、その時点の結果が返ります。タップしなければ、その後に停止しても装着者には伝わりません。
- 応答文は、どちらの背面タップで送信されたかを判別できないため、「同じようにたたく」と表現します。
