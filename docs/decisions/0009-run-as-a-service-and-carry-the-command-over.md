# 0009: launchdのサービスとして実行し、異常終了後は指示を引き継ぐ

## 状況

現場ではMacを設置したままにし、ターミナルを開かずに撮影を継続します。それまでの`field-app`は、ターミナルからの起動を前提としていました。

- 標準入力が閉じると終了の指示として扱うため、ターミナルなしで起動すると即座に終了します。
- スリープは、外部の`caffeinate`で抑止していました。
- 起動直後は目標状態を持ちません（[0002](0002-external-capture-intent.md)）。撮影継続中に異常終了して再起動すると、次の録画の区切りでループが停止し、装着者には伝わりません。

複数台を一括管理するController（Macアプリ）は、実機での動作確認が完了してから開発します。

## 決定

- 端末ごとの`field-app`を、macOSのlaunchdのサービスとして登録します（`tools/service.sh`）。ログイン時に起動し、終了したら再起動し、出力をログファイルに書き込みます。iPhone 1台につき1プロセスという構成は変更しません。Controllerを開発するまで、起動と再起動はlaunchdが担います。
- `field-app`は、ターミナルがない場合は標準入力を読まず、終了シグナルを受信するまで動作を継続します。終了シグナルの受信時は、従来どおり停止状態まで遷移してから終了します。
- `field-app`は、実行中のMacのスリープを自ら抑止します。
- Device Workerは目標状態が変わるたびにイベントを通知し、`field-app`はそれをディスクに保存します。起動時に、保存されている目標状態が`running`であれば引き継ぎます。`paused`の場合と、何も保存されていない場合は、従来どおり最初の指示を受信するまでタップしません。正常終了時は`paused`を保存するため、引き継ぐのは、撮影継続中にプロセスが異常終了した場合と、Macの電源が切れた場合のみです。
- サービスが終了しても、WebDriverAgentを実行している`xcodebuild`は残します。次の`field-app`がそのまま使用します。

## 結果

- Macにログインすれば、ターミナルを開かなくても背面タップを受信できます。`field-app`が異常終了しても、装着者の操作は不要です。
- 撮影継続の指示は、停止するまで保持されます。撮影継続中にMacが停止した場合は、Macの起動後にiPhoneと接続した時点で撮影を継続します。
- Macの再起動後は、ログインするまでサービスは起動しません。
- サービスの再登録と登録解除は、録画を停止してから行われます。
- macOSは、launchdから起動したプログラムに対しても、TCPの受信と、VPNと同種のインターフェースを経由する通信には、ローカルネットワークの許可を求めません。`field-app`の通信は、背面タップの受信と、XcodeがiPhoneとの間に維持している経路の2つで、いずれもこれに該当します。
