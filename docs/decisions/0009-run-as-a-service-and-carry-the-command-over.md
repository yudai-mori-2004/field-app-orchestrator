# 0009: launchdのサービスとして動かし、落ちた後は指示を引き継ぐ

## 状況

現場では、Macを置いたままにし、人がターミナルを開かずに撮影を続けます。それまでの`field-app`は、ターミナルから起動する前提でした。

- 入力が閉じると終了の指示として扱うので、ターミナルなしで起動すると、すぐに終わります。
- スリープは、外から`caffeinate`で防いでいました。
- 起動した直後は目標状態を持ちません（[0002](0002-external-capture-intent.md)）。撮影を続けている間に落ちて起動し直すと、次の録画の区切りでループが止まり、装着者には伝わりません。

複数台をまとめるController（Macアプリ）は、実機での確認が済んでから作ります。

## 決定

- 端末ごとの`field-app`を、macOSのlaunchdのサービスとして登録します（`tools/service.sh`）。ログインで起動し、終了したら起動し直し、表示をログファイルに出します。iPhone 1台につき1プロセスという形は変えません。Controllerを作るまで、起動と起動し直しはlaunchdが受け持ちます。
- `field-app`は、ターミナルがないときは入力を読まず、終了要求が来るまで動き続けます。終了要求では、これまでと同じく、止めた状態まで進めてから終わります。
- `field-app`は、動いている間のMacのスリープを自分で防ぎます。
- Device Workerは、目標状態が変わるたびに知らせ、`field-app`はそれをディスクに残します。起動したとき、残っている目標状態が`running`なら引き継ぎます。`paused`のときと、何も残っていないときは、これまでどおり最初の指示まで何も押しません。ふつうの終了は`paused`を残すので、引き継ぐのは、撮影を続けている間にプロセスが落ちたときと、Macの電源が切れたときだけです。
- サービスが終了しても、WebDriverAgentを動かしている`xcodebuild`は残します。次の`field-app`がそのまま使います。

## 結果

- Macにログインすれば、人がターミナルを開かなくても背面タップを受けられます。`field-app`が落ちても、装着者は何もしなくて済みます。
- 撮影を続ける指示は、止めるまで残ります。撮影を続けている間にMacが止まると、後でMacが起動してiPhoneにつながった時点で、撮影を続けます。
- Macを再起動した後は、ログインするまでサービスは起動しません。
- サービスの入れ直しと取り外しは、録画を止めてから行われます。
- macOSは、launchdから起動したプログラムにも、TCPの受信と、VPNと同じ種類のインターフェースを通る通信には、ローカルネットワークの許可を求めません。`field-app`の通信は、背面タップの受信と、XcodeがiPhoneへ保っている経路の2つで、どちらもこれに当たります。
