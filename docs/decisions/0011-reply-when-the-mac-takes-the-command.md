# 0011: 背面タップでは効果音を再生し、Macが指示を受信した時点で応答する

## 状況

[0008](0008-separate-start-and-pause-taps.md)では、背面タップの指示を受信した後、画面で結果を確認してから応答していました。録画が開始されると「撮影を開始しました。」、停止すると「撮影を終了しました。」と応答し、30秒経過しても結果が出なければ、時間がかかっていることを応答していました。

- 背面タップで開始・終了するのは、録画1本ではなく、録画を繰り返すループです。2本目以降の録画はMacが自動で開始するため、応答を1本目の録画の開始に合わせる理由がありません。
- 「撮影を開始しました。」は録画の開始後に読み上げられるため、音声が録画に含まれます。
- Macが動作していても、応答が返るのは約20秒後でした。Macに届いていない場合も何も聞こえないため、装着者は20秒ほどの間、指示が届いたかどうかを判別できませんでした。現場を移動するとWi-Fiが切断されることがあり、装着者がまず知りたいのは、Macに届いたかどうかです。
- 結果を待つために、応答を30秒で打ち切る仕組みと、時間がかかっていることを伝える応答文が必要でした。
- ショートカットは、Macに指示を送信する前に「撮影の準備をしています。お待ちください。」または「撮影を終了しています。お待ちください。」と読み上げていました。応答まで待機させることを前提とした文言です。

## 決定

- ショートカットは、まず効果音を再生してから、Macに指示を送信します。効果音は、背面タップが認識されたことを示します。
- `field-app`は、指示を受信したら即座に応答します。応答文は「撮影を開始します。」または「撮影を終了します。」です。Macが指示を受信し、ここからループを開始または終了することを示します。
- 応答の後、`field-app`は画面を読み取り、録画の開始または停止まで処理を進めます。iPhoneを操作できない間に受信した指示は、操作できるようになってから処理します。
- 途中で処理を進められなくなったことは、応答では伝えません。`field-app`のログに出力します。
- 終了処理中の`field-app`は、指示を受け付けず、応答文を返しません。

## 結果

- 効果音で背面タップが認識されたこと、続く音声でMacに届いたことがわかります。効果音に続いて音声が聞こえなければ、Macに届いていません。
- 開始の応答は、録画の開始前に読み上げられます。Minuteの実機では、応答から録画開始まで約17秒でした。終了は録画中にタップするため、効果音と応答の読み上げは録画の停止前に再生されます。
- 応答を待つ時間の上限と、時間がかかっていることを伝える応答文は廃止しました。
- 録画が開始・停止されたことは、応答ではわかりません。
