# Appium実機開発

通常運転では、Appium XCUITest Driverが実機上のWebDriverAgentを維持します。一台分のDevice Workerは、このHTTPセッションから画面を観測し、対象アプリの操作定義に従って操作を一回ずつ送ります。

## 初回セットアップ

Node.js、Appium、XCUITest Driverの版はリポジトリで固定しています。

```sh
npm run setup:appium
npm run doctor:appium
```

`mise`がある場合は`.mise.toml`のNode.jsを自動的に使用します。Appiumのドライバー本体はリポジトリ内の`.appium/`へインストールされ、Gitには含まれません。

iPhoneでは、Macとの信頼、Developer Mode、対象アプリへのログイン、必要な権限許可を初回に済ませます。WebDriverAgentの署名に使うTeamへ端末を登録します。

運用中にMacだけで立て直せるように、iPhoneの設定を次のようにします。

- パスコードをオフにする。パスコードがあると、画面がロックされたときにMacから解除できず、人が解除するまで止まる
- 自動ロックを「なし」にする。ロックされると撮影アプリが背後に回る

## 現場のネットワークとMac

- MacとiPhoneを同じネットワークにつなぐ。背面タップの指示は、iPhoneからMacへこのネットワークで届く。ゲスト用のWi-Fiのように端末どうしの通信を止めるネットワークでは届かないので、持ち込みの小さなルーターを使うと現場の設定に左右されない
- 回線の速さは問わない。録画中のやり取りは、1台あたり1分に6回ほどの短い問い合わせで、返事は合わせて数KBになる
- Macはスリープさせない。電源につなぎ、`caffeinate -i`の下で`field-app`を動かす
- WebDriverAgentの署名には、有料の開発者登録のTeamを使う。署名は1年で切れるので、切れる前に更新する

## サーバー起動

```sh
npm run appium
```

Appiumサーバーは共通で一つ起動できます。端末ごとの`field-app`プロセスが、割り当てられたMinuteまたはClaruの操作定義を読み、別セッションを作ります。各端末には異なる`FAO_WDA_LOCAL_PORT`を割り当て、その1000番後に使うMJPEGポートも重複させません。

端末UDIDと署名Team IDは環境変数で実行時だけ渡し、設定ファイルやシェル履歴を公開リポジトリへ入れません。アプリごとの起動例は[`apps/minute-app/README.md`](../../apps/minute-app/README.md)と[`apps/claru-app/README.md`](../../apps/claru-app/README.md)にあります。

各`field-app`プロセスは、最初の指示が来るまで画面を読むだけで何も押しません。録画中に起動し直しても録画は続きます。標準入力から次の命令を送ります。

- `start`: その端末を`running`（撮影を続ける）へ切り替える
- `pause`: `paused`（止める）へ切り替える。録画中なら停止し、`afterRecording`の方針で保存または破棄して、操作定義の止めた状態まで進める
- `status`: 目標状態、画面、ワーカーの状態を表示する
- `retry`: `needsAttention`の後、人が画面を確かめてから、新しい読み取りで再開する。`start`や`pause`などの新しい指示も、同じく再開の合図になる
- `quit`: 止めた状態まで進めてからセッションを閉じる。送信済みの操作があれば終わるのを待つ。`needsAttention`のときやiPhoneにつながっていないときはタップせず、止めた状態を確かめられなかったことを表示して終了コード1で終わる。Ctrl-C、終了要求、ターミナルを閉じたときも同じ

`field-app`は、読み取った画面、押した操作、ワーカーの状態の変化を、時刻つきで標準出力に出します。

複数台では、一台につき一つの`field-app`プロセスを起動し、`FAO_DEVICE_ID`、`FAO_DEVICE_LABEL`、`FAO_WDA_LOCAL_PORT`、`FAO_CONTROL_PORT`を端末ごとに分けます。ユーザー入力はiPhoneへ直接タップせず、各ワーカーの目標状態だけを変更します。

## 背面タップで止める・再開する

`field-app`は、`FAO_CONTROL_PORT`と`FAO_CONTROL_TOKEN`（16文字以上）を与えると、そのポートで`POST /toggle`、`POST /start`、`POST /pause`を受け付けます。要求には`token`パラメーターが必要です。返事は、iPhoneのショートカットが読み上げる短い文です。

```sh
FAO_CONTROL_PORT=8400 \
FAO_CONTROL_TOKEN=$(openssl rand -hex 16) \
...
```

iPhoneでは、次の手順で背面のトリプルタップに割り当てます。

1. 「ショートカット」アプリで新しいショートカットを作る。
2. 「URLの内容を取得」を追加し、URLを`http://<MacのIPアドレス>:8400/toggle?token=<トークン>`、方法を`POST`にする。MacのIPアドレスは`ipconfig getifaddr en0`で調べる。
3. 「テキストを読み上げる」を追加し、読み上げる内容を「URLの内容」にする。
4. 「設定」→「アクセシビリティ」→「タッチ」→「背面タップ」→「トリプルタップ」で、このショートカットを選ぶ。

初めて動かすときは、Macが`field-app`への接続を許可するか、iPhoneがMacへの接続を許可するかを聞くことがあります。どちらも許可します。返事が読み上げられなければ、指示はMacに届いていません。

## 長時間セッション

実機capabilityは次の方針です。

- `useNewWDA=false`で既存WebDriverAgentを再利用する。
- `noReset=true`でログイン状態とアプリデータを保つ。
- `bundleId`を指定しない。セッションを作るときも終えるときも対象アプリを起動し直さず、終了もさせないので、録画中に作り直しても撮影が途切れない。
- セッションを作った直後に`activeAppDetectionPoint`を画面の中央にする。WebDriverAgentはこの点にあるアプリを前面のアプリとして読む。コントロールセンター、通知センター、アプリの切り替え画面が開いていれば前面はシステムの画面になり、対象アプリを前面に戻す操作で閉じる。既定の点は左上にあり、通知のバナーと重なる。
- セッションを作った直後に`waitForIdleTimeout`を0にする。撮影アプリは常に画面を動かしているため、待つと1タップに20秒かかる。
- WDA起動と接続には明示的なタイムアウトと再試行回数を持たせる。
- 一台ごとにDerivedData、WDAポート、MJPEGポートを分ける。

コマンドが失敗したときは、そのセッションを捨て、10秒おきに新しいセッションを作り直します。つながらない間は`reconnecting`と表示し、人を待ちません。タップの応答が失われた場合も同じで、同じタップを再送せず、つながった後の観測から道順を決め直します。タップの応答は返ったのに画面が変わらない場合は、アプリが取りこぼしたとみなし、新しい観測から道順を決め直します。押そうとした部品がもう画面にないという応答（`stale element reference`）は、セッションが動いている証拠なので、セッションを捨てずに画面を読み直します。

`field-app`は1分ごとに電池の残量を読みます。充電していない状態で残りが10%（`FAO_BATTERY_STOP_PERCENT`で変更）になると、撮影を続けている端末に止める指示を出し、Macに通知を表示します。

二台同時運転と8時間試験では、USB/Wi-Fi切断、WDA停止、対象アプリ停止を個別に発生させ、この境界で重複操作せず復旧できることを確認します。

## 実アプリの画面要素

Minuteの画面の部品は、Minute 1.29.0で確かめた値を`apps/minute-app/definition.example.json`に書いています。アプリの更新で部品が変わったら、この定義を直します。撮るタスクだけは、ローカルの操作定義で端末ごとに与えます。対象を一つに確認できなければタップしません。
