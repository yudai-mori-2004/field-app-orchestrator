# iPhoneとMacの準備と運転

Macの`field-app`は、iPhone上のWebDriverAgentと直接やり取りします。WebDriverAgentは、XcodeがiPhoneで動かす、画面の部品を読んで押すためのアプリです。一台分のDevice Workerは、このやり取りで画面を観測し、対象アプリの操作定義に従って操作を一回ずつ送ります。

## 初回セットアップ

### Mac

Macは、使うiPhoneのiOSに対応するXcodeが動くものを使います。確かめた組み合わせは、macOS 26.3、Xcode 26.4、iOS 26.4.1のiPhone 12 miniです。Xcode 26.4.1はmacOS 26.2以降で、Xcode 27はmacOS 26.6以降で動き、macOS 26が入るMac miniはM1（2020年）以降です（[AppleのXcodeの対応表](https://developer.apple.com/support/xcode/)、[macOS Tahoe 26に対応しているコンピュータ](https://support.apple.com/ja-jp/122867)）。iOS 27のiPhoneでは確かめていません。

Macごとに、一度だけ次を済ませます。

1. Xcodeを入れて一度開き、iOSのプラットフォームを入れる。入れ終わるまで、iPhone向けの組み立てはできない。WebDriverAgentの組み立てと起動に`xcodebuild`を、iPhoneの宛先を調べるのに`devicectl`を使う
2. Xcodeの設定で、有料の開発者登録のTeamに入っているApple Accountを追加する。WebDriverAgentの署名に使う
3. このリポジトリを取得する

   ```sh
   git clone https://github.com/yudai-mori-2004/field-app-orchestrator.git
   cd field-app-orchestrator
   ```

4. Macのローカルホスト名を、役割の名前にする。理由と変え方は[現場のネットワークとMac](#現場のネットワークとmac)にある

### iPhone

iPhoneごとに、一度だけ次を済ませます。工場出荷状態のiPhoneから順に進める手順は、[iPhoneの初期設定](iphone-setup.md)にあります。

1. USBケーブルでMacにつなぎ、iPhoneに「このコンピュータを信頼しますか?」と出たら「信頼」を選ぶ。デベロッパモードをオンにする
2. iPhoneをMacと同じWi-Fiにつなぐ。一度つないだiPhoneは、それからはWi-Fiだけで操作できる
3. 撮影アプリにログインし、録画を一度手で始めて止める。カメラなどの許可は、このときに済ませる。許可の確認は操作定義にないiOSの警告なので、運転中に出ると人を待つ
4. パスコードをオフにする。パスコードがあると、画面がロックされたときにMacから解除できず、人が解除するまで止まる
5. 自動ロックを「なし」にする。ロックされると撮影アプリが背後に回る
6. 「設定」→「一般」→「情報」→「名前」で、ほかのiPhoneと重ならない名前（`minute-01`など）にする。Macの一覧で見分けるため
7. iPhoneの言語を、操作定義に書いたiOSの警告と同じ言語にする。警告は文言で見分ける。Minuteの例は日本語
8. iOSアップデートの自動インストールをオフにする。実機で確かめたiOSのバージョンのまま使うため
9. 開始と終了のショートカットを作り、背面タップに割り当てる。手順は[背面タップで止める・再開する](#背面タップで止める再開する)にある

### WebDriverAgent

WebDriverAgentは、次のコマンドで組み立てます。決まった版をnpmの登録所から取得し、照合値を確かめてから組み立てます。結果はリポジトリの`.wda/`に入り、Gitには含めません。Team IDは、Apple Developerのサイトの「メンバーシップの詳細」に出ている10文字です。

```sh
FAO_DEVELOPMENT_TEAM=<Team ID> tools/setup_wda.sh <iPhoneのUDID>
```

iPhoneを足すときは、そのiPhoneをUSBでつなぎ、そのUDIDでもう一度実行します。iPhoneがTeamに登録されます。署名は1年で切れるので、切れる前にもう一度実行します。実行すると`.wda/`を作り直すので、運転していないときに行います。

## 現場のネットワークとMac

- MacとiPhoneを同じネットワークにつなぐ。Macからの操作も、背面タップの指示も、このネットワークを通る。ゲスト用のWi-Fiのように端末どうしの通信を止めるネットワークでは届かないので、持ち込みの小さなルーターを使うと現場の設定に左右されない
- 回線の速さは問わない。録画中のやり取りは、1台あたり1分に6回ほどの短い問い合わせで、返事は合わせて数KBになる
- Macは電源につなぐ。`field-app`は、動いている間Macをスリープさせない。MacBookはふたを閉じるとスリープするので、開けたままにする
- Macのローカルホスト名を、役割の名前（`field-mac`など）にする。背面タップのショートカットは、この名前でMacに届く。どの現場のMacにも同じ名前を付けると、iPhoneはどの現場でもショートカットを直さずに使える。Macを替えるときも、新しいMacに同じ名前を付け、`config/local/`の設定を写す。ポートとトークンが同じなら、ショートカットはそのまま届く。1つのネットワークにMacを2台置くときだけ、名前を分ける。名前は、Macの「システム設定」→「一般」→「共有」の下にある「ローカルホスト名」で変える

## 起動と指示

iPhone 1台につき、`field-app`を一つ起動します。端末ごとに次の環境変数を与えます。設定ファイルやシェル履歴を、公開リポジトリへ入れません。

| 環境変数 | 内容 |
| --- | --- |
| `FAO_DEVICE_ID` | iPhoneのUDID |
| `FAO_DEVICE_LABEL` | 画面の表示に使う名前。省略するとUDID |
| `FAO_CONTROL_PORT`、`FAO_CONTROL_TOKEN` | 背面タップの受け口。端末ごとにポートを変える |
| `FAO_BATTERY_STOP_PERCENT` | 止める電池の残量（1〜50）。省略すると10 |
| `FAO_WDA_XCTESTRUN` | WebDriverAgentの組み立て結果。省略すると`.wda/`のもの |

アプリごとの起動例は[`apps/minute-app/README.md`](../../apps/minute-app/README.md)と[`apps/claru-app/README.md`](../../apps/claru-app/README.md)にあります。

各`field-app`プロセスは、最初の指示が来るまで画面を読むだけで何も押しません。録画中に起動し直しても録画は続きます。撮影を続ける指示の間に前のプロセスが落ちていたときだけは、その指示を引き継ぎます（[サービスとして動かす](#サービスとして動かす)）。ターミナルから起動したときは、次の命令を入力できます。

- `start`: その端末を`running`（撮影を続ける）へ切り替える
- `pause`: `paused`（止める）へ切り替える。録画中なら停止し、`afterRecording`の方針で保存または破棄して、操作定義の止めた状態まで進める
- `status`: 目標状態、画面、ワーカーの状態を表示する
- `retry`: `needsAttention`の後、人が画面を確かめてから、新しい読み取りで再開する。`start`や`pause`などの新しい指示も、同じく再開の合図になる
- `quit`: 止めた状態まで進めてからセッションを閉じる。送信済みの操作があれば終わるのを待つ。`needsAttention`のときやiPhoneにつながっていないときはタップせず、止めた状態を確かめられなかったことを表示して終了コード1で終わる。Ctrl-C、終了要求、ターミナルを閉じたときも同じ

`field-app`は、読み取った画面、進めた一歩、ワーカーの状態の変化を、時刻つきで標準出力に出します。

## サービスとして動かす

現場では、`field-app`をmacOSのlaunchdのサービスとして登録します。Macにログインすると起動し、落ちたときは起動し直されます。iPhone 1台につき、サービスを1つ登録します。

```sh
tools/service.sh install config/local/minute-01.env config/local/minute.json
```

1つ目の引数は、そのiPhoneの環境変数を書いたファイルです。`FAO_DEVICE_LABEL`がサービスの名前になるので、iPhoneごとに変えます。2つ目の引数は操作定義です。

```sh
FAO_DEVICE_ID=<IPHONE_UDID>
FAO_DEVICE_LABEL=minute-01
FAO_CONTROL_PORT=8400
FAO_CONTROL_TOKEN=<16文字以上のトークン>
```

- 表示は`~/Library/Logs/field-app/<FAO_DEVICE_LABEL>.log`に出る。ターミナルがないので、指示は背面タップか、`FAO_CONTROL_PORT`への要求で出す
- `field-app`を更新したときや設定を変えたときは、同じコマンドをもう一度実行する。組み立て直し、動いているサービスを止めてから、新しいもので起動する
- 外すときは、`tools/service.sh remove config/local/minute-01.env`を実行する
- 入れ直しや取り外しでサービスを止めると、`field-app`は`quit`と同じく、止めた状態まで進めてから終わる
- 撮影を続けている間に`field-app`が落ちたときは、起動し直した`field-app`が指示を引き継ぎ、続きから進める。指示は`~/Library/Application Support/field-app/`に残している。止めた後と、ふつうに終了した後は引き継がず、最初の指示まで何も押さない
- サービスが終了しても、WebDriverAgentは動き続け、次の`field-app`がそのまま使う
- サービスが起動するのは、Macにログインしたとき。Macを再起動した後は、ログインする

## 背面タップで止める・再開する

`field-app`は、`FAO_CONTROL_PORT`と`FAO_CONTROL_TOKEN`（16文字以上）を与えると、そのポートで`POST /start`と`POST /pause`を受け付けます。要求には`token`パラメーターが必要です。

```sh
FAO_CONTROL_PORT=8400 \
FAO_CONTROL_TOKEN=$(openssl rand -hex 16) \
...
```

指示を受け取ると、`field-app`はすぐに、iPhoneのショートカットが読み上げる短い文を返します。`/start`には「撮影を開始します。」を、`/pause`には「撮影を終了します。」を返します。

返事は、Macが指示を受け取り、ここから撮影のループを始める、または終えることを表します。録画が始まったこと、止まったことは表しません。`field-app`は、返事のあとに画面を読んで、録画を始める、または止めるところまで進めます。Minuteの実機では、返事から録画が始まるまで約17秒、録画を止めて説明カードに戻るまで約11秒でした。

- iPhoneを操作できない間（Wi-Fiが切れてつなぎ直している間など）に受け取った指示にも同じ文を返し、操作できるようになってから進める
- 途中で進めなくなったこと（操作定義にない警告が出ているときなど）は、返事では伝えず、`field-app`の表示に出す。もう一度背面をたたくと、画面を読み直して進める
- 終了の処理に入った`field-app`は、指示を受け取らず、文を返さない

iPhoneでは、開始と終了のショートカットを1つずつ作り、背面タップに割り当てます。

1. 「ショートカット」アプリで新しいショートカットを作り、名前を「開始」にする。
2. 「サウンドを再生」を追加する。何も設定しない。
3. 「URLの内容を取得」を追加し、URLを`http://<Macのローカルホスト名>:8400/start?token=<トークン>`、方法を`POST`にする。ポートとトークンは、このiPhoneの`field-app`に与えたものにする。ローカルホスト名は、[現場のネットワークとMac](#現場のネットワークとmac)で決めた名前に`.local`を付けたもの（`field-mac.local`など）で、MacのIPアドレスが変わっても同じ名前で届く。
4. 「テキストを読み上げる」を追加し、読み上げる内容を「URLの内容」にする。
5. 同じ手順で「終了」のショートカットを作る。3のURLの`/start`を`/pause`にする。
6. 「開始」と「終了」を、ショートカットアプリの中で1回ずつタップして動かす。「“開始”が“〜.local”に接続することを許可しますか?」と聞かれたら、「常に許可」を選ぶ。
7. 「設定」→「アクセシビリティ」→「タッチ」→「背面タップ」で、「トリプルタップ」に「開始」を、「ダブルタップ」に「終了」を選ぶ。

6で`field-app`が動いていれば、録画が始まり、止まります。Macが`field-app`への接続を許可するかを聞いたときは、許可します。

最初の効果音はiPhoneの中だけで鳴らすので、Macに届いたかどうかに関係なく鳴ります。これが聞こえなければ背面タップが認識されていません。効果音に続いて声が聞こえなければ、指示はMacに届いていません。

## WebDriverAgentとのつながり

- `field-app`は、XcodeがiPhoneへ保っている経路のアドレスで、WebDriverAgentに話しかける。アドレスは`devicectl`で調べるので、Wi-FiでもUSBでも同じ形で届き、IPアドレスを固定しなくてよい。どのiPhoneのWebDriverAgentも同じポートで待ち受ける
- WebDriverAgentが返事をしないときは、iPhoneに届くことを確かめてから、`xcodebuild`で起動し直す。起動には5〜10秒かかる。iPhoneに届かない間（Wi-Fiの外にいるときなど）は起動し直さず、戻るのを待つ。そのまま戻れば、録画も途切れない
- 3回起動しても返事がなければ、署名の期限切れなどとみなし、Xcodeの出力を表示して人を待つ
- WebDriverAgentは`field-app`を終えても動き続け、次に起動した`field-app`がそのまま使う
- セッションでは対象アプリを指定せず、画面の中央にあるアプリを前面のアプリとして読む。コントロールセンター、通知センター、アプリの切り替え画面が開いていれば前面はシステムの画面になり、対象アプリを前面に戻す操作で閉じる。対象アプリを指定すると、これらの下にあるアプリを前面として読み、部品を押せるものとして返すので、タップがコントロールセンターに当たる。既定の判定の位置は左上で、通知のバナーと重なる
- セッションを作った直後に`waitForIdleTimeout`を0にする。撮影アプリは常に画面を動かしているため、待つと1タップに20秒かかる

コマンドが届かないときや、WebDriverAgentのセッションがなくなったときは、そのセッションを捨て、10秒おきに作り直します。つながらない間は`reconnecting`と表示し、人を待ちません。タップの応答が失われた場合も同じで、同じタップを再送せず、つながった後の観測から道順を決め直します。タップの応答は返ったのに画面が変わらない場合は、アプリが取りこぼしたとみなし、新しい観測から道順を決め直します。部品がもう画面にないという応答（`stale element reference`）は、読んでいる途中でも押す途中でも、画面が先へ進んだ証拠として扱い、セッションを捨てずに読み直します。押すはずのボタンがないなど、そのほかの断りの応答では、人を待ちます。

`field-app`は1分ごとに電池の残量を読みます。充電していない状態で残りが10%（`FAO_BATTERY_STOP_PERCENT`で変更）になると、撮影を続けている端末に止める指示を出し、Macに通知を表示します。

## 実アプリの画面要素

Minuteの画面の部品は、Minute 1.29.0で確かめた値を`apps/minute-app/definition.example.json`に書いています。アプリの更新で部品が変わったら、この定義を直します。撮るタスクだけは、ローカルの操作定義で端末ごとに与えます。対象を一つに確認できなければタップしません。
