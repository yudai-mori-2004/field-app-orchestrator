# 動作確認状況

実機での動作確認の結果と、未確認事項、既知の問題をまとめています。仕組みは[アーキテクチャ](architecture.md)、運用方法は[運用](operation.md)を参照してください。

## 動作確認環境

| 項目 | 内容 |
| --- | --- |
| 撮影アプリ | Minute Data 1.29.0（英語表示） |
| iPhone | iPhone 12 mini 2台（iOS 26.4.1、iOS 26.5.2）、言語設定は日本語 |
| Mac | MacBook Air（M1）、macOS 26.3、Xcode 26.4 |
| 接続方法 | Wi-Fiのみ（USBケーブル未接続） |

試験中の録画は、提出されないよう、すべて破棄しています。

## 撮影ループ

- 30分の区切りで上限到達のダイアログを閉じて録画を破棄し、20〜25秒で次の録画を開始する。サービスとして実行し、1台で6回連続（3時間14分）を確認。2台を同時に実行した3時間の間も、それぞれ5回以上連続して処理した
- タスク一覧、他のタブ、タスクカードのいずれの画面からも、対象のタスクを検索して録画を開始する
- 停止時は、録画を停止して破棄し、カメラを閉じたタスクカードで待機する。1分未満の録画で表示されるダイアログにも対応する
- カウントダウン中のキャンセルで表示される確認ダイアログ（Cancel the recording?）では、撮影継続時は「Keep going」、停止時は「Yes, cancel」をタップする
- 保存の流れ（保存、確認、同じタスクで続行）は1回確認済み

## 背面タップ

- 背面タップのショートカットから開始と終了を送信すると、効果音に続いて応答文が読み上げられ、録画が開始・停止される
- 応答は0.1秒未満で返る。タスクカードからの開始は応答から約17秒で録画中になり、録画中からの終了は応答から約11秒でタスクカードに戻る
- ホーム画面や他のアプリの表示中に開始を送信しても、撮影アプリを前面に戻して録画を開始する
- カウントダウン中に再度開始を送信しても、タップは行わない。カウントダウン中に終了を送信すると、カウントダウンをキャンセルしてタスクカードに戻る
- Wi-Fiをオフにした状態で背面をタップすると、効果音のみ再生される。Wi-Fiをオンに戻すと、その指示がMacに届いて応答文が読み上げられ、指示どおりに処理される
- ショートカットの「方法」が`GET`の場合、ログに`control port answered 405`と出力され、音声応答はない
- 終了処理中の`field-app`は、指示を受け付けず、応答文を返さない

## 画面操作への対応

- 停止後にiPhoneが次の状態にあっても、開始を送信すると録画を開始し、終了を送信すると停止する: 他のアプリ、ホーム画面、コントロールセンター、通知センター、Appスイッチャー、検索、画面ロック、Minuteの終了、Minuteの未定義の画面（設定内の画面）、タブを覆うシート（言語設定）、末尾までスクロールしたタスク一覧
- 撮影継続中にホーム画面に移ると、Minuteは録画を停止する。1分未満の録画は破棄されてタスクカードに戻り、1分以上の録画は録画完了画面に残る。いずれの場合も、`field-app`がMinuteを前面に戻して次の録画を開始する
- 撮影継続中にコントロールセンターを開いても、Minuteは録画を継続する。通知センターを開くと、`field-app`がロック画面として解除の操作を行い、Minuteは録画を停止する。`field-app`が録画完了画面を処理して次の録画を開始する
- 撮影継続中に手動で録画を停止すると、1分未満・1分以上のいずれでも、`field-app`が破棄して次の録画を開始する
- 撮影継続中に画面がロックされると、Minuteは録画を停止して録画完了画面に遷移する。`field-app`はロックを解除して録画完了画面を処理し、約20秒で次の録画を開始する
- 撮影継続中にMinuteが終了されると、録画途中のデータは失われる。`field-app`はMinuteを再起動してタスクを検索し、約80秒で録画を再開する
- 停止中に手動で録画を開始しても、`field-app`はタップを行わない。次の指示を受信すると、その時点の画面から処理する
- カメラへのアクセス許可がないiPhoneで開始を送信すると、Minuteがアクセス許可を求めるシートを表示し、`field-app`はタップを行わずに停止する
- 未定義のアラートが表示されている状態で開始を送信すると、処理を進めずに停止する。アラートを閉じてから再度開始を送信すると、録画を開始する

## 接続断と再起動

- 撮影継続中にiPhoneのWi-Fiをオフにしても、Minuteは録画を継続する。約1分後にオンに戻すと、`field-app`は再接続して画面を読み取り、録画中のまま処理を継続する
- WebDriverAgentが終了されても、`field-app`が再起動し、約14秒で操作を再開する。録画は中断されない
- WebDriverAgentの停止中に開始を受信すると、WebDriverAgentを再起動し、約30秒後に録画を開始する
- 撮影継続中にiPhoneを再起動すると、録画途中のデータは失われる。iPhoneの起動後、`field-app`がWebDriverAgentを再起動し、Minuteを起動してタスクを検索し、電源オフから約2分で録画を再開する
- 録画中に`field-app`を再起動しても、録画は停止しない
- 撮影継続の指示を受信した直後に`field-app`を強制終了すると、launchdが1秒で再起動し、再起動した`field-app`が指示を引き継いで録画を開始する
- サービスを停止すると、録画を停止して破棄し、タスクカードまで遷移してから終了する。次回起動時は、最初の指示を受信するまでタップを行わない
- `quit`とCtrl-Cでは、停止状態まで遷移してから終了する
- `field-app`の実行中は、Macのスリープを抑止する
- 画面が変化しない間の問い合わせは、1分あたり7回

## バッテリー

- iOSのバッテリー残量のアラート（残り20%、10%）を「閉じる」で閉じ、録画を継続する
- 充電していない状態でバッテリー残量が低下すると、撮影を停止して録画を破棄し、タスクカードで待機する。停止の設定値を10%にしていたが、5%で停止した。バッテリー残量の取得処理を修正済みだが、修正後の動作は未確認
- 充電しながら撮影を継続すると、バッテリー残量は10%から80%まで増加し、80%以降は横ばいだった
- 充電せずに撮影を継続した場合、1%の減少に2.4〜3分かかった（Wi-Fiのみ、iOS 26.5.2の端末）。満充電から停止までの時間は計測中

## セットアップ

- GitHubからクローンした状態から、ドキュメントのコマンドで、操作定義の作成、WebDriverAgentのビルド、サービスの登録、録画の開始と終了まで実施できる。XcodeとiPhoneの信頼設定が完了しているMacで確認
- 2台目（iOS 26.5.2）をドキュメントに従って準備し、2台のサービスを同時に稼働させた

- 設定アプリの項目名は、iPhone 12 mini（iOS 26.4.1）の実機で確認。初期設定の画面とショートカットの項目名は、iOS 26.4のローカライズ文字列で確認

## 既知の問題

- タップ後約8秒経過しても画面が遷移しない場合、`field-app`は同じボタンを再度タップする。録画の開始・停止、保存、破棄のボタンも対象となる。撮影アプリがタップを受け付けていて、画面の遷移が遅れているだけの場合は、同じボタンを二重にタップすることになる。これまでに再タップが発生したことはない
- `field-app`がボタンを覆う表示を検出するのは、タップの直前のみ。カウントダウンや録画中の画面に未定義の表示が重なっても、背後の画面の識別要素を読み取れるため、検出できずに待機し続ける
- 通知センターをロック画面として扱うため、通知センターが表示されるとロック解除の操作を行い、その結果Minuteが録画を停止する
- Wi-Fiの切断中に送信した背面タップの指示は、Wi-Fiの復旧時に遅れて届く。ショートカットの待機時間の上限は未確認
